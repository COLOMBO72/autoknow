# autoknow — движок + сайт

Два отдельных проекта, запускаются как два отдельных процесса (два терминала):

- **backend/** — autoknow-engine, NestJS + PostgreSQL, порт **3000**
- **frontend/** — autoknow-frontend, Next.js, порт **3001**

## Что понадобится

- Node.js 20+
- PostgreSQL (локально или в облаке) — просто пустая база, схему накатит Prisma
- Ключ AITUNNEL (или другого OpenAI-совместимого агрегатора) — без него бэкенд поднимется, но генерация отчётов будет падать с ошибкой авторизации у провайдера
- Ключи ЮKassa — не обязательны для первого теста: без них не будет работать реальное пополнение баланса, но весь остальной функционал (выбор машины, генерация отчёта, сравнение, кабинет, авторизация) проверяется и без них

## Шаг 1 — backend

```bash
cd backend
npm install
cp .env.example .env
```

В `.env` обязательно заполнить:
- `DATABASE_URL` — строка подключения к твоей PostgreSQL
- `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` — данные от AITUNNEL
- `JWT_SECRET` — любая длинная случайная строка (для теста подойдёт что угодно, для прода — сгенерировать нормально, например `openssl rand -hex 32`)
- `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` — можно оставить как есть, если пока не тестируешь пополнение

Дальше:

```bash
npx prisma generate
npx prisma migrate dev --name init
npm run start:dev
```

Бэкенд поднимется на `http://localhost:3000`.

## Шаг 2 — frontend

В новом терминале:

```bash
cd frontend
npm install
cp .env.local.example .env.local
npm run dev
```

Проверить, что в `.env.local` `NEXT_PUBLIC_API_BASE_URL=http://localhost:3000` (по умолчанию уже так).

Открыть `http://localhost:3001` — это и есть сайт.

## Проверка, что всё работает

1. На главной выбрать любую машину из списка (например Kia → Rio → 2019) и нажать «Показать досье» — должен запуститься реальный запрос к ИИ (занимает несколько секунд, идёт живой поиск).
2. На странице отчёта — «Добавить к сравнению», выбрать вторую машину так же, зайти в `/compare`.
3. `/account` — баланс (изначально 0 ₽, поэтому первый запрос отчёта скорее всего упадёт с ошибкой «недостаточно средств» — это ожидаемо и правильно; чтобы проверить сам факт генерации отчёта без реальной оплаты, проще всего один раз вручную поднять баланс тестовому пользователю через Prisma Studio: `npx prisma studio` в папке backend → таблица User → отредактировать `balanceKopeks`).
4. `/login` — регистрация/вход, `/forgot-password` — запрос сброса (ссылка на сброс попадёт не на почту, а в лог бэкенда в терминале — реальная отправка писем ещё не подключена, см. `backend/src/modules/auth/email.service.ts`).

## Известные упрощения (не баги)

- Личный кабинет и баланс работают через анонимный id в cookie, пока человек не зарегистрируется — подробности в комментариях `frontend/lib/session.js`.
- Письма (сброс пароля) не отправляются по-настоящему, только логируются на бэкенде.
- Список марок/моделей для дропдаунов — вручную собранные ~25 моделей в `backend/src/data/car-seed-dataset.ts`, остальное — see README внутри `backend/`.
