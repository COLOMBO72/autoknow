# autoknow-engine

Backend-движок AI-помощника по покупке авто. Рабочее название проекта — **autoknow**
(домен ещё не закреплён — см. обсуждение вариантов в переписке).

Ключевая идея архитектуры: движок ничего не знает о клиенте. Сегодня клиент —
веб-сайт (PWA), позже может добавиться telegram-бот для СНГ вне РФ и мобильное
приложение — всё это отдельные тонкие клиенты поверх этого же API.

## Принятые решения (чтобы не забыть, почему именно так)

- **Канал для MVP — сайт (PWA), не Telegram-бот.** Причина: с февраля 2026
  Роскомнадзор замедляет/блокирует Telegram в РФ, а это основная аудитория
  продукта. Бот остаётся вариантом для расширения на СНГ вне РФ позже — архитектура
  это уже поддерживает без переделок.
- **AI-провайдер — агрегатор (OpenAI-совместимый API), не прямой OpenAI.**
  Причина: прямой доступ из РФ формально закрыт и грозит банами волнами без
  предупреждения — неприемлемый риск для сервиса, который держит деньги
  пользователей на балансе. `AggregatorAiProvider` абстрагирован через
  `baseURL`/`apiKey` из `.env`, плюс встроен fallback на вторую модель.
- **Модель, а не свой скрапер drom/drive2.** Юридически рискованно и
  технически дорого поддерживать скрапер против антибота. Вместо этого:
  батчем собирается и пересказывается своими словами референсный датасет
  (`CarContextProvider` — сейчас заглушка, см. TODO), модель форматирует его в
  структурированный отчёт. См. раздел "Как наполнить датасет" ниже.
- **Кэш — по блокам, не по отчёту целиком.** У `SPECS`/`PROBLEMS` TTL ~9-12
  месяцев, у `PRICE` — 10 дней (самый волатильный). См. `report-ttl.policy.ts`.
  Компромисс MVP: если хоть один блок устарел — перегенерируется весь отчёт
  одним вызовом модели (это дешевле и проще, чем частичная регенерация;
  стоимость токенов пренебрежимо мала).
- **Оплата — ЮKassa**, переиспользуй реальную интеграцию с velium.ru,
  `yookassa.service.ts` — это каркас по стандартному паттерну их API, а не
  проверенный рабочий код (заполни idempotence-логику и проверку подписи
  вебхука по своему рабочему примеру).
- **Лимит сравнения — 3-5 машин** (`COMPARISON_MAX_CARS` в `.env`).
  Для сравнения все машины должны быть куплены — при повторном сравнении уже
  купленной машины деньги повторно не списываются (см. `hasPurchased`).

## Как наполнить датасет (замена ручному парсингу drom/drive2)

`CarContextProvider.getContextChunks()` сейчас возвращает `[]`. План на Phase 0:

1. Вручную (или полуавтоматически) собрать 20-30 популярных на СНГ-рынке
   моделей: характеристики двигателей, консенсус по типичным проблемам,
   диапазон цен. Источники — открытые каталоги, агрегированная статистика,
   форумные обсуждения (пересказанные своими словами, не копипаст).
2. Сложить в простую таблицу/JSON, подключить чтением в `CarContextProvider`
   вместо заглушки.
3. Прогнать 10-15 реальных моделей через `ReportsService.getOrGenerateReport`,
   вручную сверить адекватность цифр перед тем как пускать реальных
   пользователей.
4. Обновлять датасет периодически (cron), особенно блок цен — чаще, чем
   характеристики.

## Известные упрощения (не баги, осознанный MVP-компромисс)

- `checklistBeforeBuying` не кэшируется отдельным блоком — при чистом
  кэш-хите возвращается пустым. Если это критично — вынести в отдельный
  `ReportBlockType.CHECKLIST` с TTL как у `SPECS`.
- Нормализация бренда/модели (`normalize()` в `reports.service.ts`) — только
  `trim().toLowerCase()`. Синонимы ("Рио" → "Kia Rio") пока не резолвятся —
  нужен словарь синонимов, иначе кэш будет хуже матчиться, чем мог бы.
- Проверка вебхука ЮKassa — только по `event`/`status`, без сверки подписи и
  IP отправителя. Обязательно доделать перед продакшеном.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить реальные ключи
npx prisma generate
npx prisma migrate dev --name init
npm run start:dev
```

Важно: в этой песочнице `npx prisma generate` падает с 403 при попытке
скачать engine-бинарник (`binaries.prisma.sh` не в белом списке доменов
контейнера) — это ограничение именно текущей среды Claude, не проблема кода.
На твоей машине с обычным доступом в интернет команда отработает штатно.
TypeScript-компиляция всего остального (`tsc --noEmit`) уже проверена и
проходит чисто.

## Дальше (следующие шаги)

1. Выбрать конкретного агрегатора (протестировать 2-3 на реальном промпте
   из `car-report.prompt.ts`) и модель — вписать в `.env`.
2. Наполнить `CarContextProvider` реальными данными по Phase-0 списку моделей.
3. Поднять Postgres (локально или в облаке) и прогнать миграции.
4. Начать фронтенд (PWA) поверх `POST /reports/purchase` и
   `POST /reports/compare` — личный кабинет, баланс, история покупок.
